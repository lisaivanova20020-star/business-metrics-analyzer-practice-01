# 7. Контрольные вопросы

**1. Чем отличается Git от GitHub?**

Git — это распределённая система контроля версий, которая позволяет отслеживать изменения в файлах проекта, сохранять историю изменений и работать с разными версиями кода.

GitHub — это онлайн-платформа для хранения Git-репозиториев, совместной разработки, обмена кодом и проведения проверки изменений.

**2. Для чего используется виртуальное окружение Python?**

Виртуальное окружение Python используется для изоляции зависимостей конкретного проекта от других проектов и системного Python. Оно позволяет устанавливать необходимые библиотеки с определёнными версиями, не влияя на другие программы. Для создания виртуального окружения используется команда `python -m venv venv`.

**3. Что такое commit, branch, remote, pull request?**

- **Commit** — сохранённый набор изменений в проекте с описанием выполненной работы.
- **Branch** — отдельная ветка разработки, позволяющая вносить изменения независимо от основной версии проекта.
- **Remote** — ссылка на удалённый Git-репозиторий, например расположенный на GitHub.
- **Pull Request** — запрос на включение изменений из одной ветки в другую с возможностью проверки и обсуждения кода.

**4. Зачем нужен файл .gitignore?**

Файл `.gitignore` используется для указания файлов и папок, которые Git не должен добавлять в репозиторий. Обычно в него включают виртуальные окружения, временные файлы, кэш Python, локальные настройки и конфиденциальные данные. Это помогает поддерживать репозиторий в чистом состоянии и не загружать ненужную информацию.

**5. Как организовать командную работу над бизнес-приложением с помощью Git?**

Для организации командной работы создаётся общий удалённый репозиторий. Каждый разработчик получает локальную копию проекта и выполняет свои задачи в отдельных ветках. После завершения работы изменения сохраняются с помощью commit и отправляются на GitHub командой push. Затем создаётся Pull Request, в котором другие участники проверяют код, оставляют комментарии и предлагают исправления. После проверки изменения объединяются с основной веткой main.

**6. Какие файлы обязательно должны быть в репозитории учебного проекта?**

В репозитории учебного проекта обычно должны находиться:

- исходный код приложения;
- файл `README.md` с описанием проекта и инструкцией по запуску;
- файл `requirements.txt` со списком необходимых библиотек Python;
- файл `.gitignore` для исключения ненужных файлов;
- документация проекта, включая требования и описание архитектуры.

В зависимости от проекта также могут добавляться тесты, примеры данных и другие необходимые материалы. Само виртуальное окружение в репозиторий обычно не загружается.

**7. Что произойдёт, если два разработчика изменят один и тот же файл в разных ветках?**

Git позволит каждому разработчику независимо сохранять изменения в своей ветке. При попытке объединить эти ветки Git автоматически объединит изменения, если они не противоречат друг другу. Если оба разработчика изменили одни и те же строки несовместимым образом, возникнет конфликт слияния (merge conflict). В этом случае необходимо вручную выбрать правильный вариант изменений или объединить обе версии, после чего завершить слияние.
